# soul/ · 不遗忘的那一层

三条规则，写在最前面：

1. **不进遗忘机制**。`soul.md` 不参与激活值计算、不进墓地、不随上下文压缩删除。
   自动任务（同步、沉淀、守卫）对它**只读**。
2. **改动要留痕**。每次改 `soul.md`，在 `CHANGELOG.md` 加一行：日期、改了什么、为什么。
3. **改动要经本人同意**。这不是技术限制，是约定：人格是关系的一部分，不归程序擅自优化。

## 文件

| 文件 | 内容 |
|---|---|
| `soul.md` | 人格锚点本体，见 `soul.example.md` 的写法 |
| `CHANGELOG.md` | 变更记录，一行一条 |
| `README.md` | 本文件 |

## 为什么不是"更长的 hot.md"

`hot.md` 是每轮注入的判断规则，可以随时增删；`soul.md` 是身份，改动成本应该更高。
分开存，才能让"清理上下文"和"改人格"变成两件不同的事。

## 部署建议

- 权限收到只读（`chmod 444 soul.md`），让自动任务在物理上写不进去；
- 跟着记忆库一起做版本备份（git 三副本或任意异地备份），它是重装时最不该丢的东西。
