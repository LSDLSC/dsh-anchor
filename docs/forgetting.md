# 遗忘与召回

## 为什么不用固定阈值

"30 天不访问就删除"有两个问题：
- 重要的旧事实（生日、禁忌）会被删；
- 不重要的新事实因为"新"而一直占位。

改成概率模型后，排序自然形成，删除只是极端情况。

## 公式

```
B = ln( Σ_j (t_j + 1)^(-0.5) )
A = B + 0.4 × importance + ε
P = σ(A − τ)
```

- `t_j`：第 j 次访问距今的小时数
- `importance`：1–5，身份/规矩/纪律类给 5
- `ε ~ N(0, 0.5)`：噪声，代表"突然想起来"
- `τ`：默认 -1.5，越大越难召回

## 参数建议

| 参数 | 默认 | 说明 |
|---|---|---|
| 重要性权重 | 0.4 | 5 分条目额外 +2.0 |
| 噪声标准差 | 0.5 | 想更稳定就 0.2，想更"灵光"就 0.8 |
| `access_times` 上限 | 20 | 只留最近 20 次 |
| 墓地触发 | 手动 | `memory bury --id` 或 `--query` |

## 三阶段清理

1. **降权**：什么都不做，只是很久没访问，概率自然变低。
2. **入墓**：`memory bury`，移出检索、物理保留，`memory restore` 可回。
3. **焚毁**：清墓地 + 备份，需明确确认。日常不建议用。

## 检索即复习

`memory search` 命中后自动 `tick`，追加 `access_times`。这不是"作弊"，
是把真实使用当作信号——用过的东西才值得留着。
