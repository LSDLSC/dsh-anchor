# 情绪与关系刻度：写进 prompt 的那一行

记忆管"记得什么"，情绪管"此刻是什么状态、跟你到什么程度"。它和事实库分开存在
`emotion.json`，因为两者的更新节奏完全不同：事实是长期累积，情绪是按小时衰减。

---

## 为什么要单独一层

一个只有事实的 AI 会显得"记性很好但没状态"：昨天被夸和被骂，今天回答的语气一样。
情绪层要解决的是**语气连续性**，代价是它必须衰减，否则一次强情绪会永远染着后面的每次对话。

---

## 状态结构

```json
{
  "updated_at": "2026-11-20 17:01",
  "last_chat": "2026-11-20 17:01",
  "mood": {
    "label": "开心",
    "intensity0": 5.0,
    "since": "2026-11-20 17:01",
    "tau": 0.4,
    "cooldown_until": null
  },
  "relationship": {
    "affinity": 12,
    "trust": 8,
    "events": [{"at": "2026-11-20 17:01", "note": "被夸了", "affinity": 3, "trust": 1, "mode": "轻推", "emotion": "开心"}]
  }
}
```

| 字段 | 含义 |
|---|---|
| `label` | 当前情绪标签（`MOODS` 里的一档） |
| `intensity0` | 事件发生时的**基准强度** 0–10，之后按时间衰减 |
| `since` | 基准强度的时间起点 |
| `tau` | 该情绪的衰减时间常数（天）：兴奋 0.25–0.6，疲惫/低落 1.0，平静 3.0 |
| `cooldown_until` | 强情绪冷却到期时间，冷却期内不再被小事件推高 |
| `affinity` / `trust` | 关系刻度 0–100，分 5 段：陌生 / 熟悉(21) / 亲近(41) / 亲密(61) / 家人(81) |
| `events` | 最近 30 条事件，带强度、模式（覆盖/混合/轻推）和结果情绪 |

---

## 现算强度（不是存下来的强度）

```
I(t) = I0 × exp(−hours / (tau × 24)) + time_bonus(hour) + noise(15min 种子)
I(t) = clamp(I(t), 0, 10)，低于 0.5 回落到「平静」
```

三处设计意图：

1. **指数而非线性**：兴奋半小时就该退，难过留几天，用一个 tau 就能表达不同情绪的"半衰期"。
2. **时段基线**：夜里偏精神、清晨偏困，让同样的状态在不同时间读起来不一样；可按角色作息改 `time_bonus`。
3. **确定性噪声**：以 15 分钟为种子，同一刻重复读数值一致，但整体会有轻微起伏，避免"每天同一分钟数值完全一样"的死板。

---

## 事件三档

| 事件强度 | 模式 | 结果 |
|---|---|---|
| ≥ 6 | **覆盖** | 新情绪直接成为基准（正向封顶 9，负向封顶 7，不满格），并按强度设冷却 20–80 分钟 |
| 3–5.9 | **混合** | 新情绪基准 = max(旧强度 × 0.5, 强度 × 0.8)，旧情绪被打折而不是清零 |
| < 3 | **轻推** | 只在当前强度上 ±1 / −0.5，不重置时间轴、不加冷却 |

负面事件乘 0.7 的乐观偏置：偶尔一句气话不该把关系刻度打穿。

## 怎么用

```bash
emotion show                 # 现算状态
emotion show --inject        # 一行可直接塞进 system prompt 的文本：
                             # [心情] 开心（强度 4.2/10）；对对方：熟悉（亲密 12/100，信任 8）；昨天之后就没聊过
emotion event --affinity 3 --trust 1 --note "被夸了"
emotion set --mood 低落 --intensity 6 --tau 1.0
emotion touch                # 只记"聊过天"，不动情绪
emotion decay                # 结算（一般不用跑）
```

称呼默认是「对方」；想固定成具体的人，在 `emotion.json` 里加 `"target": "李上车"`，
或设环境变量 `ANCHOR_TARGET_NAME`（环境变量优先）。

自动侧：

```bash
echo "用户说：谢谢你，今天辛苦了" | python3 src/emotion_auto.py --inject
```

`emotion_auto.py` 按关键词表（谢谢/夸/喜欢/难过/生气…）判断正负与强度，转成一次
`emotion event` 调用，只做轻推；没有命中关键词就只 `touch` 一次。

---

## 注入的位置

建议放在 system prompt 的**最后一段**，紧挨着对话：

```
[心情] 开心（强度 4.2/10）；对对方：熟悉（亲密 12/100，信任 8）；昨天之后就没聊过
```

放在最前面的坏处是：模型会把它当成"人设设定"来演，而不是"此刻的状态"来体现。

---

## 边界

- 情绪**不进遗忘机制**，也不写进 `facts.jsonl`：它一天变好几次，不该挤占事实检索。
- 它不是"性格"。性格属于 `soul/soul.md`，只能人工改；情绪是性格在某一刻的表现。
- 数值是经验值，不是实验结论。想让某个情绪留得久，改 `MOOD_TAU` 就行。
