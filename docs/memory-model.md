# 记忆模型：四层 + 一个墓地

一句话：**按"该不该被清理"分层，而不是按"重不重要"分层。**

---

## 四个层

| 层 | 文件 | 内容 | 谁改它 | 会被清理吗 |
|---|---|---|---|---|
| L1 常驻 | `hot.md` | 每轮都要注入的判断规则 | 人，随时 | 不会被自动清理，但可以人工精简 |
| L2 事实 | `facts.jsonl` | 一行一条的可检索事实 | `memory add` | 会降权、会进墓地 |
| L3 经历 | `journal/YYYY-MM-DD-*.md` | 会话原文摘要 | 沉淀任务 | 一般不动，靠归档 |
| L4 交接 | `state.json` | 上一次做到哪、下一步做什么 | 人 / 任务 | 覆盖式更新 |
| 人格 | `soul/soul.md` | 身份、关系、底线 | 只能人工改 | **永不** |

为什么要分：

- 清理上下文时只该动 L2、L3，不该顺手把人设和底线"优化"掉；
- 单层文件损坏不会牵连全局——`state.json` 解析失败时，`facts.jsonl` 照样能读；
- 每层的写入者只有一类，冲突面小。

---

## 事实条目的字段

```json
{"id":"a1b2c3d4","ts":"2026-11-20 20:41","text":"用户偏好先给结论","tags":["偏好"],"importance":4,"access_times":["2026-11-20 20:41"]}
```

| 字段 | 说明 |
|---|---|
| `id` | 稳定哈希，`bury` / `restore` 靠它定位 |
| `ts` | 首次写入时间 |
| `text` | 一句话事实，不含过程 |
| `tags` | 分类，也参与默认重要度判定（身份/规矩/纪律=5，偏好/环境/项目=4，其余 3） |
| `importance` | 1–5，可显式指定；不指定则按标签推 |
| `access_times` | 每次被检索命中追加一次，决定"多热" |

## 遗忘：ACT-R 激活，不是到期删除

```
B = ln( Σ_j (t_j + 1)^(-0.5) )     # t_j：第 j 次访问距今小时
A = B + 0.4 × importance + ε        # ε ~ N(0, 0.5)
P = σ(A − τ)                        # τ 是召回阈值，默认 0
```

三处设计意图：

1. **没有硬边界**。不是"30 天没读就删"，而是概率逐渐降低；最近读过的一次就能把条目拉回来。
2. **噪声项**。让久未访问的条目偶尔"突然想起来"，避免记忆库变成只记得最近事情的东西。
3. **检索即复习**。命中一次就写一次 `access_times`，下次更容易被想起——这是"常用记忆自然变重要"的机制。

`activation.py` 就是这套算法的可执行版本：

```bash
python3 src/activation.py score          # 按召回概率排序
python3 src/activation.py tick --id <id> # 手工记一次访问
```

## 删除分三级

| 级别 | 做法 | 可逆 | 什么时候用 |
|---|---|---|---|
| 1 降权 | 不写 `access_times`，自然沉底 | 是 | 默认，什么都不用做 |
| 2 墓地 | `memory bury`，移出检索、原文保留 | 是，`restore` 随时回来 | 明确"不想再被想起来的旧事" |
| 3 焚毁 | 清墓地 + 清备份 | **否** | 只有敏感信息或本人明确要求，且需确认 |

绝大多数"该忘"的东西停在第 2 级。第 3 级是例外路径，不是常规操作。

---

## 检索时的顺序

`memory search` 只读 L2。`memory handoff` 按这个顺序拼：

```
soul.md  →  hot.md  →  state.json  →  命中的 facts（按时间倒序，带标签）
```

`soul.md` 永远在最前，因为它不该被任何检索结果顶掉。

---

## 和上下文压缩的关系

上下文压缩（把长会话折叠成摘要）动的是**对话历史**；记忆库动的是**跨会话的长期状态**。
两者是不同层，别互相替代：

- 只做压缩：换一个会话就什么都不记得；
- 只做记忆库：单次会话太长仍然会爆上下文；
- 两个都做：压缩管"这次聊了啥"，记忆库管"这个人是谁、做到哪了"。
