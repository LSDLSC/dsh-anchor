# 缺陷与缺失（诚实的自述）

这个仓库是从一个人的真实故障里长出来的，不是成熟产品。下面把已知的坑列清楚，
免得后来的人踩同样的坑，也免得我们高估它。

## 一、已知缺陷

### 1. 锁防不了宿主进程
`workspace_guard.py` 用 `fcntl.flock` 只保证**守卫之间**不互踩。宿主（DSH 进程）自己
在内存里维护 sessionIds，退出时整体写回——这个覆盖发在锁外，守卫拦不住。

**后果**：两个宿主同时跑，最坏情况仍会丢登记。
**根治**：单宿主（推荐），或从 DSH 侧改成"合并写"（我们改不了别人的写入路径）。

### 2. 定时检查有窗口期
守卫每小时跑一次，会话丢失到被修复之间最长一个小时。这期间 UI 是空的。
**方向**：改为 inotify 监听 `workspace.json` 变更即时修复（见"缺失功能"）。

### 3. Windows 上无锁
`fcntl` 是 POSIX 的，Windows 退化为"无锁 + 写前合并"。窗口更大，但逻辑仍正确。
**方向**：用 `msvcrt.locking` 或文件占位锁替代。

### 4. 与 DSH 版本强绑定
目录命名规则（`--path--`）、`workspace.json` 的 schema、会话文件格式
（`session.v4.jsonl.zstd`）都随 DSH 版本变。升级后可能失效。
**方向**：启动时校验版本，不匹配就拒绝运行并给出提示，而不是静默改错。

### 5. 检索是关键词，不是语义
`memory.py search` 做的是子串/标签匹配。同义表述检索不到。
**方向**：可选接入 embedding（本地向量模型），但会引入依赖，与"零依赖"冲突，
所以只做插件式扩展，不进核心。

### 6. 参数是经验值
ACT-R 的 `0.4` 重要性权重、`ε=0.5` 噪声、`τ=-1.5`，情绪的半衰期表，
都是拍脑袋调的，没有 A/B 数据支撑。
**方向**：收集真实使用日志后回归，别把这个仓库当"实验结论"。

### 7. 没有自动化测试，没有 CI
目前只有手工冒烟测试：造一个临时 `DSH_HOME`，跑守卫，看输出。
**这是最大的缺口**——"可复现"三个字现在还撑不起来。

### 8. 只在 Linux 验证过
`quickstart/install.sh`、systemd 单元、shell 脚本都只在 Ubuntu 24.04 跑过。
Windows 需要任务计划程序，macOS 未验证。

### 9. 裸仓不自动创建
`dsh-memory-sync.sh` 假设 `$BARE_DIR/<name>.git` 已存在（`git init --bare`）。
脚本不会帮你建，缺了就静默跳过。

## 二、缺失功能（按价值排序）

1. **实时修复**：inotify / ReadDirectoryChangesW 监听注册表，变更即修，不等定时器。
2. **自动化测试 + CI**：pytest 覆盖三种坏注册表（数字时间戳 / 缺登记 / 双写覆盖），
   GitHub Actions 跑 lint + test。
3. **干净环境复现**：一个 `docker compose up` 就能看到"坏 → 修 → 好"全过程。
4. **告警通道**：`anchor status` 退出码之外，支持 webhook / 邮件 / 桌面通知。
5. **版本校验**：DSH 版本不匹配时拒绝运行，而不是改错。
6. **迁移工具**：从其他记忆系统（SillyTavern、MemoryOS）导入 facts。
7. **语义检索**：可选 embedding，插件式。
8. **Windows 任务计划模板**：和 systemd 对等的 `.ps1` + `schtasks` 命令。

## 三、求优化

这个仓库的目标不是"完美"，是**把一次真实故障的解法留下来**，让踩同样坑的人少走弯路。

如果你遇到以下情况，欢迎提 Issue 或 PR：

- 你的 DSH 版本上目录规则变了 → 告诉我新规则，我改 `session_dir_of()`
- 你遇到过别的会话/记忆丢失方式 → 开 Issue 描述复现路径，比功能建议有用得多
- 你有生产环境的记忆系统 → 说说这和你的方案差在哪
- 你想补测试 / CI / Docker → 直接 PR，不用先问

**特别欢迎**：
- 能复现"双宿主覆盖"的测试用例（我们现在只能模拟，没法自动化验证真实覆盖）
- 跨平台（Windows/macOS）的适配
- 对参数（重要性权重、噪声、τ、半衰期）的实证建议

## 四、不要指望它做的事

- 不是 DSH 官方项目，不保证兼容未来版本
- 不做"全自动记忆整理"（用 LLM 重写记忆很容易把事实写歪）
- 不替代 DSH 自己的会话存储，只是给它加一层守卫
- 不收集任何遥测，所有数据都在本地
